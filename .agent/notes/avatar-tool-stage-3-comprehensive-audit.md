# Avatar 用户自定义道具阶段 3 全面审查

## 1. 总结

阶段 3 的主功能方向正确：编辑器已经使用实际初始图片作为唯一入口，鼠标点击和延时切换均为完整互动，支持图片不变、自连接、回连、分支、用户选边、折线/曲线显示、概览、重命名和保存前校验。旧 v2 两种模式的编辑投影、独立编辑窗口以及 N.E.K.O.-PC 文件选择器父窗口也符合当前阶段边界。

但本轮按设计、架构、状态、边界情况、用户操作、性能、语言、可访问性、测试和阶段 4 接口契约重新审查后，确认仍存在会影响当前用户体验或下一阶段正确接入的问题。现有 `23` 个前端测试文件、`580` 项测试、TypeScript 类型检查和生产构建通过，只能证明已覆盖路径没有回归，不能覆盖本文列出的反例。

## 2. 当前阶段 3 必须修正的问题

### 2.1 折线路由可能穿过未纳入搜索范围的节点

- 级别：阻断收口
- 位置：`frontend/react-neko-chat/src/avatar-tools/avatarToolEdgeRouter.ts`
- 当前行为：正交寻路先以起终点外扩固定 `96px` 形成筛选范围，只让范围内节点参与搜索；后续生成的外侧走廊可能越过该范围，但返回路径没有再对全部节点做最终复核。
- 已确认反例：
  - source：`{ x: 502, y: 419, width: 202, height: 82 }`，从下边出发；
  - target：`{ x: 327, y: -7, width: 228, height: 104 }`，从上边进入；
  - 另一节点：`{ x: 718, y: 175, width: 228, height: 104 }`；
  - 返回路径包含从 `(722, 531)` 到 `(722, -37)` 的竖线，直接穿过该节点；节点互不重叠且存在清晰绕行空间。
- 根因：参与搜索的障碍范围与最终允许生成的路线范围不一致。
- 修正验收：折线路径返回前必须对完整实际节点集合验证；筛选可以保留，但不得遗漏最终路线实际经过范围内的节点。新增上述确定性回归用例和路线不穿过非端点节点的性质测试。

### 2.2 障碍移走后增量路由会永久保留无必要绕路

- 级别：阻断收口
- 位置：`frontend/react-neko-chat/src/avatar-tools/avatarToolEdgeRouter.ts`
- 当前行为：增量失效只判断旧路径是否穿过障碍内部。旧路径沿扩展边界绕行时不算相交，障碍节点移走后该连接不会重算。
- 已确认反例：source 与 target 水平相对，中间障碍使原路线向上绕行；把障碍从 `y=0` 移到 `y=300` 后，增量规划仍直接复用旧六点路线，而同一新布局的完整规划为两点直线。
- 根因：缓存只记录了路径结果，没有可靠记录该路径依赖的障碍或净空边界；旧障碍离开也没有触发“路线是否还能简化”的检查。
- 修正验收：障碍进入和离开既有路线净空范围都能准确使受影响连接失效；不要求每次移动全图重算，未受影响连接仍应复用。

### 2.3 无关编辑会清空整张图尚未修正的校验错误

- 级别：阻断收口
- 位置：`AvatarToolInteractionEditorContext.tsx`、`AvatarToolCreatePage.tsx`
- 当前行为：除选择外的所有 action 都会清空全部 issues 并增加 `graphRevision`。保存失败后，只要拖动节点、改名或只修一个字段，其它仍存在的不可达、歧义、缺少动作等错误也全部消失；页面总错误提示同步被清空。
- 结构原因：画布几何变化、互动语义变化和校验反馈生命周期共用同一个 revision 与全量清理策略。
- 用户影响：错误看似已经解决，实际再次保存时才重新出现；拖动仅调整布局也会清除错误。
- 修正验收：布局移动不清理语义错误；字段修改只清理或重新计算相关错误；其它未修正错误持续可见、可定位。

### 2.4 高扇出时连接落点和命中区域重新重叠

- 级别：高
- 位置：`avatarToolEdgeRouter.ts` 的 `laneOffsets`、`AvatarToolEditorWorkspace.tsx` 的 `interactionWidth`
- 当前行为：侧边连接数量增加时，落点间距会被压缩到固定侧边范围内；竖侧达到约 8 条连接后，实际间距已经小于 `12px` 命中宽度，相邻线难以稳定独立选择。
- 文档差异：实施记录只验证了少量连接时 `14px` 间距与 `12px` 命中宽度，没有覆盖间距被压缩后的情况。
- 修正验收：结合后端连接数量上限确定可支持规模；在允许上限内，同侧连接仍有可区分落点和可操作命中区。必要时使用分组、分层或随实际间距收窄的命中策略，但不能恢复离散可见端口。

### 2.5 初始图片入口错误摘要是无效按钮

- 级别：中
- 位置：`AvatarToolInteractionInspector.tsx`
- 当前行为：错误摘要把所有 issue 都渲染为按钮，但 `initial-connection-required` 没有 interaction ID 或 link ID，点击后不执行选择、聚焦或定位。
- 文档差异：阶段 3 实施记录声明错误摘要可点击并自动定位实际问题。
- 修正验收：该错误要么提供真实的画布定位/聚焦行为，要么不伪装成可点击控件；保存失败后的首个错误定位也应覆盖初始入口。

### 2.6 Escape 不区分局部关闭与关闭整个编辑器

- 级别：中
- 位置：`AvatarToolStandaloneEditor.tsx`
- 当前行为：窗口级 `keydown` 捕获所有未处于输入法组合态的 Escape，立即关闭编辑页；不判断概览位置菜单、下拉控件或其它局部交互是否应先处理该键，也不检查事件是否已被消费。
- 用户影响：用户本想关闭菜单或退出局部状态时，可能直接关闭整个未保存的编辑页。
- 范围说明：锁定设计不要求自动保存或草稿，本问题不据此扩大为草稿功能；只要求 Escape 行为具有正确上下文。
- 修正验收：局部浮层先响应 Escape；焦点处于编辑控件或事件已处理时不关闭窗口；窗口关闭继续交由明确关闭操作承担。

### 2.7 语言切换后图片引用位置可能残留旧语言

- 级别：中
- 位置：`AvatarToolCreatePage.tsx` 的 `actualImageReferences`
- 当前行为：引用位置字符串在 `useMemo` 内通过 `i18n` 生成，但依赖只有 `imageReferences` 和 `interactionState`。独立窗口响应 `localechange` 后外层重新渲染，该 memo 不一定失效。
- 用户影响：切换语言后立即删除被互动引用的图片，外层错误可能已经是新语言，内部“鼠标点击 / 按下时 / 松开时 / 到时”仍是旧语言；只有互动状态再次变化后才会刷新。
- 修正验收：语言版本成为所有缓存本地化派生值的明确依赖；新增切换语言后直接触发引用删除提示的回归测试。

### 2.8 Web 降级文件选择无法可靠重选同一个 MP3

- 级别：中
- 位置：`AvatarToolCreatePage.tsx` 普通音效和彩蛋音效 `<input type="file">`
- 当前行为：图片选择后会清空 input 值，两个音效 input 的 `onChange` 没有清空。删除音效后再次选择相同文件时，部分浏览器不会再次触发 `change`。
- 范围说明：N.E.K.O.-PC Host 原生选择器不受影响；问题存在于没有 Host picker 的 Web 降级路径。
- 修正验收：普通音效和彩蛋音效均可在删除后重新选择同一个文件，并有对应测试。

## 3. 阶段 4 接入前必须明确和补齐的契约

### 3.1 校验器会接受部分悬空的初始图片连接

- 级别：阶段 4 阻断
- 位置：`avatarToolInteractionEditorModel.ts` 的 `validateAvatarToolInteractionGraph`
- 已确认反例：一个合法点击自循环，`initialImageTargetIds = ["ix-a", "ix-missing"]`。因为至少保留一个有效目标，当前校验返回空数组，没有报告 `ix-missing`。
- 当前/未来边界：正常阶段 3 reducer 不会由界面制造该状态；阶段 4 从磁盘读取、迁移或处理损坏数据后，该缺口会变成真实数据完整性问题。
- 修正验收：每个初始连接目标都必须存在；严格 decoder 与保存前 validator 都覆盖悬空目标。

### 3.2 严格读取边界尚未覆盖编辑状态全部不变量

- 级别：阶段 4 阻断
- 当前状态：`reset` 直接接受完整状态；当前 v2 投影来源受控，但未来 v3 detail 不能把未知 JSON 直接送入 reducer。
- 待覆盖不变量：
  - 重复 interaction ID、link ID 和初始连接目标；
  - 非法 `sourceSide/targetSide`；
  - 非有限节点坐标；
  - 普通连接悬空端点；
  - `initialImageLinkSides` 中的陈旧目标；
  - 图片动作引用不存在的 image ID；
  - 未知字段、未知 trigger/action 类型和超限数组。
- 修正验收：阶段 4 由严格 decoder 在进入编辑状态前拒绝或按明确迁移规则处理，不依赖 TypeScript 类型断言。

### 3.3 后端 limits 缺少互动、连接和延时上限

- 级别：阶段 4/5 阻断
- 位置：`localTools.ts` 的 `LocalAvatarToolLimits`
- 当前状态：只有工具、名称、描述、图片和资源上限；互动节点、连接和最大延时没有权威上限，前端也可无限添加。
- 延时边界：当前解析接受任意正的安全整数；例如 `2147483648ms` 可以通过，而浏览器单次 `setTimeout` 通常受 32 位延时上限约束。
- 性能影响：规模不受控时，路由、可达性、歧义检查、React 状态派生和高扇出命中都会同时退化。
- 修正验收：由后端统一下发节点数、连接数和最大延时，前端只消费同一限制；Store、Router、Web/PC 严格契约和运行解释器使用同一值或共享 fixture，不另写互相矛盾的常量。

### 3.4 v3 manifest 示例无法表达当前全部编辑状态

- 级别：阶段 4 阻断
- 位置：实施文档 5.1 的 v3 权威记录示例
- 当前缺口：
  - 没有初始连接的 `sourceSide/targetSide`；
  - 普通 links 没有 `sourceSide/targetSide`；
  - 阶段 3 使用稳定 `link-*` ID，但文档没有决定持久化还是按确定规则重建；
  - 尚未把新增 limits 写进共享响应契约。
- 修正验收：阶段 4 开始编码前先用 Web、Python Store/Router 和 PC 共享的严格 fixture 锁定字段；保存并重新打开后，用户选择的连接两端边界、节点位置和连接身份保持一致。

## 4. 架构与性能问题

### 4.1 Context 更新粒度过大

- `AvatarToolInteractionEditorContext` 同时广播完整 state、issues、图片状态和 graphRevision；任一部分改变会唤醒所有消费者。
- 节点拖动的每个位置 action 都增加 graphRevision，并使创建页执行额外状态更新。
- `actualImageReferences` 依赖整个互动 state，纯位置变化也会重算全部图片引用。
- 节点默认序号通过反复 `find/filter/findIndex` 计算；节点数组重建时形成不必要的重复扫描。
- 图验证中的可达性和候选集计算也多次扫描完整 links/items，必须建立在明确规模上限之上。

修正方向应是区分语义 revision 与几何 revision、拆分或选择性订阅 Context，并预建 ID/序号/引用映射；不能只继续优化路由器而忽略其外层 React 与数据派生成本。

### 4.2 文件职责仍然过度集中

- `AvatarToolEditorWorkspace.tsx` 约 `1173` 行，同时包含工作区壳、画布、节点、边、连接预览、概览、偏好、路由缓存与用户事件。
- `avatarToolEdgeRouter.ts` 约 `1364` 行，混合几何、路径搜索、端口分配、增量失效、路线评分和 SVG 输出。
- `AvatarToolCreatePage.tsx` 约 `891` 行，继续承担页面协调、资源选择、表单校验、互动校验和阶段边界提示。

行数本身不是错误，但当前混合职责已经使“筛选范围与最终路径不一致”“几何变化清空语义错误”等跨职责问题难以被测试锁定，与实施文档提出的组件拆分方向不一致。整改应围绕职责和可独立验证的不变量拆分，不做无关重构。

### 4.3 遗留样式

`styles.css` 中仍保留 `.avatar-tool-workspace-empty*` 样式，但阶段 3 当前 JSX 已没有对应结构。属于低优先级清理项，不应与功能修正混成大范围格式化或重写。

## 5. 可访问性与键盘体验

- 概览位置区域使用 `role="menu"` / `menuitemradio`，但没有完整的方向键、Escape、焦点进入和关闭后焦点恢复规则；当前 Escape 还会直接关闭整个窗口。
- 道具设置/互动设置使用 `role="tab"`，但没有 `aria-controls`、对应 `tabpanel` 和页签方向键行为。
- 四条连接边界暴露完全相同的可访问名称，不能说明上、右、下、左；同时尚未证明键盘用户可以建立连接。
- 图片卡片上的初始标识为 `aria-hidden`，列表浏览时按钮名称不说明该图片是否为初始图片，只有进入详情后才能从 radio 获知。

这些项目不改变连续边界、不增加可见圆点，也不扩展产品语义；属于成熟编辑器应补齐的输入与反馈层。

## 7. 自动化测试缺口

现有测试应保留，并至少补充：

1. 最终路径超出初始筛选范围后仍不得穿过任何非端点节点；
2. 障碍移入和移出旧路径净空范围都能正确局部失效；
3. 保存失败后移动节点不清空语义错误，修正单项不清空其它错误；
4. 一个有效、一个悬空的初始连接目标必须报错；
5. v3 严格解码拒绝重复 ID、非法边、非有限坐标、悬空引用和超限数组；
6. 最大允许延时与超限延时；
7. 高扇出允许规模内的落点、命中区和选线；
8. localechange 后直接显示新语言的图片引用删除提示；
9. Web 删除音效后可重选同一个 MP3；
10. 概览菜单打开时 Escape 只关闭菜单，不关闭编辑器；
11. v2 `click-advance` 投影的完整链与尾部行为；
12. 保存并重新打开后用户选定的连接起止边保持一致。

## 8. 已检查且当前不作为问题的内容

- 初始图片是唯一真实入口，没有开始节点或“起始互动”属性；
- 鼠标点击按完整节点连接，按下和松开只是内部图片时机；
- 延时切换允许图片不变，完成后仍可沿连接继续；
- 自连接、回连、完整循环、没有后续连接均为合法结构；
- 同一等待位置的重复点击和相同延时能够被当前校验识别；
- reducer 正常界面路径会阻止重复普通连接和悬空端点；
- 用户选择的普通连接和初始连接起止边在当前编辑内会保留；
- 曲线只恢复 Bézier 显示，不要求曲线避障；
- v2 `press-swap` 与 `click-advance` 当前编辑投影与原运行视觉过程一致；
- 当前阶段不保存 v3、不接入 Web/PC 图运行时，属于明确阶段边界，不按缺陷处理；
- N.E.K.O.-PC 独立编辑窗口为普通可移动、可缩放窗口，图片和音效选择器会以编辑窗口作为父窗口；
- 不因本次审查扩大为自动保存、草稿、复杂终止性分析、自动布局或通用状态机功能。
